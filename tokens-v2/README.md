# tokens-v2 (Vitae 27)

New token set for the Vitae 27 library. Built alongside the current `tokens/` folder, which stays in place and keeps the live Storybook working until v2 replaces it.

- `primitives.json` — Phase 1, signed off 10/16/26. Raw values only, no meaning: one cool neutral ramp (010–220), brand ramps for EA, DC, MA and ME (005–190, with 100 as each client's brand color), status ramps, metal and program colors, spacing, radius, border widths, type sizes, line heights, weights, families, motion and two elevations.
- Mirrors the **Primitives** collection in the [Vitae 27](https://www.figma.com/design/FgVdwGszfnY0vz75yxfJ7F) Figma file. Figma code syntax uses `var(--vitae-<path>)`, for example `var(--vitae-color-dc-primary-100)`.
- `brand/{ea,dc,ma,me}.json`: Phase 2, signed off 10/16/26. Brand roles per client: the three ramps as `brand.*`, brand-tinted light-mode text, the dark-mode button picks, font family and radius. Phase 3 (Button, 10/16/26) added outline/ghost text colors per client and mode, the dark hover/pressed tints, and moved dark solid buttons to near-white fills (primary 010, secondary and tertiary 020). Mirrors the **Brand** collection (modes EA, DC, MA, ME) in Figma.
- `semantic/{light,dark}.json`: Phase 2, signed off 10/16/26. 81 color roles (background, field, border, text, icon, action, support). Phase 3 added 20 outline/ghost button roles (`action.*-text*`, `action.*-subtle-*`), borders for every alert (`support.*-border`), and for Input (10/16/26) `field.border-active` and `field.background-active`, with `field.border` and `field.border-hover` now pointing at per-client blends (`brand.light|dark.field-border*`: 20% and 60% of the way from the grey rest border to the active border). Mirrors the **Color** collection (modes Light, Dark). Pick one brand file and one semantic file to get any of the 8 combinations.
- Text styles (26) live in Figma, with the font family bound to `brand/font/family`: headings H1–H6 and Dialog; Body (Regular, Bold, Label, Button, Input, Helper); table; navigation (Breadcrumb, Breadcrumb Current, Filter Heading); **Link** (Link/Body, Link/Body Hover, Link/Label, Link/Small, Link/Small Hover — renamed 10/20/26 from Body/Link, Body/Link Hover, Body/Label Link and Navigation/Breadcrumb Hover; the underline is part of each style, so always apply the Link style rather than underlining text by hand); and **Label** (Label/Badge 12/16 for count badges, Label/Tagline 12/16 Bold for the drawer tagline). Body/Input is 16/20 (text inside fields); Body/Helper is 14/20 (helper and error text).

- Program tags (10/20/26): `color.program.*-dark` and `*-dark-surface` primitives added for Healthy DC Plan (DC) and Clear Choice Plan (ME); semantic `program.dc-healthy-*` and `program.me-clear-choice-*` roles in both light and dark. Use only in the matching client.
- Tier 4 navigation (10/20/26):
  - Brand: `brand.light|dark.nav-*` (accent, rule, bar, admin-bar, admin-text), `brand.dark.nav-drawer`, `brand.light|dark.footer-*` (bg, lang-bg, pill) and `brand.light|dark.progress-upcoming`. Dark nav bars use DC secondary 170 and EA/MA/ME primary 150.
  - Semantic: `nav.*` (accent, rule, bar, admin-bar, admin-text, bar-text, badge, badge-text, drawer, item-hover, item-pressed, item-selected, panel), `footer.*` and `progress.upcoming` (always used at 40% opacity; gray for DC).
  - Boolean switches (`$type: boolean`, not part of DTCG; map them to a CSS class or data attribute): `logo.show-color` / `logo.show-white` (semantic: color logo in light, all-white in dark) and `progress.connector-gapped`, `progress.connector-continuous`, `progress.current-center-dot` (brand: EA/MA/ME use gapped connectors, DC continuous; all use an open ring for the current step).
  - Components that use them: Header, Footer and mobile drawer; Breadcrumbs; Pagination; Left nav (2px hover bar at 40%, 4px selected bar); Mobile nav toggle (shared by Left nav and Progress); Progress and Progress line (Ends=Rounded on desktop, Flush under the mobile toggle); Tabs (underline, horizontal scroll on mobile).
- Tier 5 plan shopping (10/21/26):
  - Primitives: `color.metal.*-border` (darker shade of each metal fill) and program tag colors `color.program.dc-essential*`, `color.program.me-current-plan*`, `color.program.ma-premium-value*` (each with dark-mode values).
  - Semantic: `metal.<level>`, `metal.<level>-text`, `metal.<level>-border` for bronze, silver, gold, platinum and catastrophic (black text on bronze, silver and gold; white on platinum and catastrophic; same in both modes); `card.surface` (neutral/200 in dark so brand color is reserved for the selected state); `table.row-hover`, `table.row-selected`; `program.dc-essential-*`, `program.me-current-plan-*`, `program.ma-premium-value*`.
  - Changed: `text.body` is now neutral in every client (neutral/170 light, neutral/030 dark; was brand-tinted). DC `brand.light.nav-accent` now uses primary 100 (dark blue) for the header role label, links and role icon.
  - Brand: `brand.radius.card-focus-ring` (12px). Booleans `filter.show-healthy-dc-plan`, `filter.show-essential-plan` (DC), `filter.show-clear-choice-plan` (ME), `fieldset.show-county` (ME). Strings (`$type: string`, not part of DTCG; use as copy): `filter.network-local` (EA and MA values are placeholders) and `fieldset.address-line-1-label` (DC asks for the quadrant).
  - Components that use them: Metal badge, Card, Accordion, Table, Filter, Plan tile, Tag, Field-set.
  - Responsive components (decided 10/21/26): components are built once and reflow with width instead of separate desktop and mobile versions; anything that cannot flex in Figma is written as a developer note in the component description (for example full-width buttons below 480px). Plan tile, Field-set, Footer, Tabs, Table, Pagination, Breadcrumbs and Filter panel follow this; Header, Left nav and Progress keep separate mobile patterns. Where the narrow version is a different pattern rather than a reflow, it is its own type or component (Pagination Compact, Back link, Filter panel Sheet).
- Tier 5 follow-ups (10/21/26):
  - Two-tone warning icon: `support.warning-icon-fill` (primitive `color.status.warning-icon`, #f5c400), `support.warning-icon-ink` (neutral/190) and `support.warning-icon-outline-color` (dark outline in light mode, matches the fill in dark mode). The bright yellow is only ever used with the dark "!", which carries the contrast.
  - `support.warning-border` light now uses warning/100 (bright amber) instead of warning/130.
  - `alert.text`: title and message text in every alert type (neutral/150 light, white dark), separate from body copy.
  - Renamed: `table.header-bg` → `surface.header-bar` (CSS `--vitae-table-header-bg` → `--vitae-surface-header-bar`); tables no longer use a header fill, the Plan tile header bar does.
  - Brand (Log-in): `login.show-official-banner` (MA only, matches mass.gov), `login.official-banner-text`, `login.official-domain-title`, `login.official-domain-text`, `login.show-system-notice` (DC), `login.help-phone` and `login.help-phone-tel` (E.164 for `tel:` links; every phone number is a tel: link). EA phone values are placeholders.
  - Icons: every icon is exported at its full frame (16, 20 or 24px square viewBox, padding included), never cropped to the artwork.
- Plan compare and responsive pass (10/21/26). No new tokens; component changes that affect markup and CSS:
  - Plan compare: full page, not a modal; up to 3 plans; one value per benefit. Rows are 48px (12px padding + 24px line, border inside). Plan header has Size=Default and Size=Compact; the header row is `position: sticky; top: 0` and switches to Compact once the full header scrolls out of view (same DOM, extra parts hidden with CSS). Select plan always sits at the bottom of each plan column.
  - Compare tray: background `surface.header-bar`; last element of the main content with `position: sticky; bottom: 0`, so it settles above the footer at the end of the page. There is no empty Compare page: with fewer than two plans, go back to results and show an Info alert ("There are no plans to compare"), focus on its heading.
  - `surface.header-bar` now also used for Compare section rows and the Compare tray.
  - Tabs: Scroll left / Scroll right properties (fade + chevron when tabs overflow; drag and swipe still scroll). Table: select-all checkbox in the header when rows are selectable; header row has no fill and a strong bottom border.
  - Pagination: `Layout` (Desktop / Tablet / Mobile) replaced by `Type` (Full / Compact). Full wraps the controls below the summary when space runs out; use Full when the container is at least 560px wide, Compact below.
  - Breadcrumbs: `Depth=Mobile` removed. New **Back link** component ("Back to {parent}", Arrow Left 20, built from Link / Standalone); use it in place of Breadcrumbs under 768px, inside `<nav aria-label="Breadcrumb">`. Also used for "Back to plans" on Compare.
  - Footer: on narrow widths the help and contact links align left once they wrap below the copyright; DC contact links pull back by the ghost button padding (`margin-inline-start: calc(-1 * var(--vitae-space-016))`).
  - Filter panel: `Layout` renamed to Expanded / Collapsed / Sheet. Expanded groups sit in 3 equal columns (`grid-template-columns: repeat(3, 1fr)`, `space.032` gaps): Plan level, Plan type, Network + Plan features; then Carrier, Premium, Deductible. Below 768px a "Filters" button opens the Sheet. Catastrophic is a fifth option in Plan level (no helper text), shown only to people who qualify.
  - Carrier filter is multi-select: on desktop the field opens **Filter/Carrier list** (checkboxes on the Menu surface, optional search above 8 carriers) and summarizes the choice ("CareFirst BlueChoice", "2 carriers", "All carriers"); in the Sheet it is a plain checkbox group. Build it as a `button[aria-expanded]` plus a `fieldset` of native checkboxes, not `select[multiple]`. Carrier names are DC placeholders until each client's list is confirmed.
- Icons (10/22/26): Fluent System Icons, copied exactly at 16, 20 and 24 in Regular and Filled, one "Shape" layer colored by `icon.primary` (use `fill="currentColor"` in code). Added Clock, Location, Wallet, Shield, People Team, Chat Multiple, Building and Arrow Sort (sortable table headers). The header icons (User Consumer, User Expert, User Settings, Building, Building Retail, Cart Filled, Translate) now live on the Icon page at the one size the Header uses (four are 32px).
- Build and Storybook (10/22/26): `npm run build:v2` (part of `npm run build`) writes `dist/v2/css/vitae.css` with one block per client and mode, `[data-client="dc"][data-mode="dark"] { --vitae-… }` (EA light is also the `:root` default), plus per-combination CSS and JSON and `dist/v2/docs/manifest.json` (every token with its CSS variable, type and description). Storybook has a Mode toolbar control next to Theme and a **Vitae 27/Foundations** section generated from these files: semantic color roles, client ramps, text styles, spacing, radius and borders, elevation, motion and client settings.
- Components bind every color, spacing (`space.*`), radius (`radius.*`, `brand.radius.*`), border width (`border-width.*`), shadow (Elevation styles) and text style to a token (audited 10/20/26). Exceptions: client logo artwork, and fixed element sizes such as 44px rows.

Status surfaces use step 015 of each status ramp (decided 10/16/26).
